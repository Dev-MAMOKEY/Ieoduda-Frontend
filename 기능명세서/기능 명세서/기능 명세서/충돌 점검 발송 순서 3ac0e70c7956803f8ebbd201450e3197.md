# 충돌 점검 / 발송 순서

기능: 자료 보존과 업무 인계가 정리·삭제보다 먼저 실행되도록 이메일 발송 단계를 구성합니다.
대상: 계획 작성자
분류: Web Browser

#### **진입 조건**

담당자와 행동이 등록된 후 진입합니다.

#### **표시 요소**

의존 관계 그래프, 순서 목록, 담당자 수락·대체 담당자 상태와 충돌 카드를 표시합니다.

대표 충돌: “클라우드를 먼저 정리하면 가족사진과 납품 파일을 더 이상 인계할 수 없습니다.”

#### **사용자 액션**

단계 순서를 수정하고 최대 대기 시간과 대체 담당자를 확정합니다.

#### **API 호출**

- 충돌 검사: `POST /api/plans/{planId}/conflicts/check`
- 의존 관계 저장: `PUT /api/plans/{planId}/dependencies`
- 발송 단계 저장: `PUT /api/plans/{planId}/release-stages`

#### **예외 처리**

순환 의존 관계, 수락 담당자 누락과 대체 담당자 부재를 경고합니다.
